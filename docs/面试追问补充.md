# MoneyMate · 深度追问补充（针对"功能多但深度一般"的扣分点）

> 面试官觉得功能多但深度不够时，会从这几个点深挖。每题给出"原理 + 本项目怎么做的 + 改进空间"。

## Q1. 统计接口的 Redis 缓存怎么保证数据一致性？

- **原理**：缓存一致性常见三种策略——失效（写时删缓存）、更新（写时同步更新缓存）、过期（TTL 兜底）。强一致还要配合数据库事务和双删。
- **本项目**：统计接口读时先查缓存、未命中回源数据库并写缓存；写流水时删统计相关缓存 key，下次读取重新计算。TTL 作为兜底防止脏数据长期存在。
- **改进空间**：删缓存和写库不是原子的，极端情况可能短暂读到旧数据；生产可加消息队列做最终一致，或对统计结果容忍几秒延迟即可。

## Q2. 多钱包余额是怎么保证不出现负数的？

- **原理**：余额是聚合值，多个操作并发改同一个钱包时，需要用事务 + 行锁（`SELECT ... FOR UPDATE`）或乐观锁（版本号）保证原子性。
- **本项目**：单笔流水在事务里先查钱包余额做校验（够不够扣），再更新余额，同一时刻只有一个连接能改，教学场景够用。
- **改进空间**：高并发下应改为"流水驱动"——余额不直接改，而是查询时 SUM 流水计算，避免并发写冲突；或者加乐观锁版本字段。

## Q3. AI 记账解析是怎么实现的？解析错了怎么办？

- **实现**：调 LLM API，用提示词让模型从一句话里提取金额、分类、钱包，返回结构化 JSON；前端展示解析结果，用户确认后才入账。
- **防错**：解析结果不直接写库，用户可改；未配置 API key 时优雅降级为手动选择。
- **改进空间**：可以加"解析置信度"或让模型返回原句中的关键字段做二次校验；也可以收集解析失败样本做 Prompt 迭代（评测集思路，和超市项目一致）。

## Q4. CSV 导入怎么做到自动去重？

- **做法**：按支付平台、流水时间、金额、交易号组合算指纹，导入前先查库去重；同时兼容 GB18030 编码和不同列名。
- **改进空间**：大批量导入用批量插入 + 唯一索引兜底，比逐条判断更稳。

## Q5. 为什么用 SQLModel 不用纯 SQLAlchemy？

- 答：SQLModel 是 SQLAlchemy 2.0 + Pydantic 的融合，模型类即数据表定义，接口层复用 Pydantic 校验，代码量少一半；底层还是 SQLAlchemy，切 MySQL 只改连接串。

## Q6. 演示数据为什么每次重启都会初始化？

- 答：免费托管实例磁盘不持久，重启后数据库是空的，所以启动时检测空库自动生成 demo 账号和样例账单，保证演示站永远有内容。真实产品会用托管 PostgreSQL。

## Q7. JWT 过期了怎么办？怎么让用户重新登录？

- 答：前端 axios 拦截器捕获 401 后清除本地 token 跳转登录页。本项目 token 1 天过期；生产可加 refresh token 双令牌机制。
