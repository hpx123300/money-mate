# 📝 开发记录（面试讲故事用）

> 记录真实开发过程与踩坑经历。面试被问「这个项目怎么做的」，从这里挑故事讲。

## 2026-08-08：项目启动

### 为什么做记账系统

目标是找第一份 AI 应用/后端实习。调研后发现：实习生项目的关键是「完整、可信、讲得清」，而不是技术多高端。选记账系统是因为：

- 需求清晰、人人理解，演示无门槛；
- 覆盖全栈核心点：认证、CRUD、统计、导出、部署；
- 能展示数据分析能力（图表），和我的信息管理专业背景匹配。

### 技术选型（及理由）

| 选择 | 理由 |
|---|---|
| FastAPI | Python 主流 API 框架，自动文档，简历认可度高 |
| SQLModel | SQLAlchemy 2.0 + Pydantic 融合，一张类一张表 |
| JWT + Argon2 | 当前业界标准的无状态认证与密码哈希 |
| Vue3 + TS + Element Plus | 国内主流前端栈，中文资料多 |
| ECharts | 图表生态成熟，统计页直接可用 |
| SQLite | 零配置起步，代码留好 MySQL 切换位 |

### 实现顺序（先引擎后车壳）

1. 数据模型：User / Category / Transaction / Budget；
2. 认证：注册（自动建 11 个默认分类）→ 登录 → JWT；
3. 业务：流水 CRUD + 筛选、预算、统计、CSV 导出；
4. 测试：11 项自动化测试；
5. 前端：登录页 → 记账页 → 统计页 → 预算页 → 分类管理；
6. Docker 两阶段构建。

### 踩坑记录

**坑 1：新版 Starlette 测试客户端需要 `httpx2`**
现象：装完依赖跑测试直接报错。解决：查报错信息，补依赖。收获：版本升级会带来生态变化，报错信息是第一个线索。

**坑 2：TestClient 不进入 with 上下文就不会建表**
现象：接口测试报「no such table」。解决：测试里显式调用 `init_db()`。收获：FastAPI 的 lifespan 只在服务器真正启动时执行。

**坑 3：pnpm 11 默认拦截依赖构建脚本**
现象：Vite 依赖 esbuild 的构建脚本被 pnpm 拦下，安装报错。解决：查官方文档，配置 `pnpm-workspace.yaml` 的 `allowBuilds`。收获：新版包管理器的安全策略，读官方文档比猜快。

**坑 4：静态文件路径配错 404**
现象：前端构建完页面打不开。解决：统一 `backend/app/static` 为前端产物目录。收获：前后端路径约定要在项目一开始就定清楚。

### 第二波：加自己的功能（同日）

按「让自己有真实需求」的思路补了两个功能：

**多钱包**
- 需求来源：我微信、支付宝、现金各有一点钱，混在一起记根本看不出哪个快没了；
- 实现：新增 Wallet 表，流水挂到钱包下，钱包余额 = 初始余额 + 收入 - 支出，自动算；
- 彩蛋：做了一个「轻量迁移」——给旧数据库自动补 `wallet_id` 列、给老用户自动建默认钱包并把历史流水归进去，数据不丢。这个以后面试可以讲。

**月度总结**
- 需求来源：记账的目的是搞清楚钱花哪了，但看一堆数字太累；
- 实现：纯规则生成一段人话——总收支、花钱最多的分类、最大单笔、奶茶/外卖点了多少次、预算还剩多少。没调 LLM，零成本，逻辑完全可解释。
- 效果：「奶茶点了 1 次，共花了 ¥30.00。支出超过收入啦，看看哪块能省一省。」——这种话让项目变得有生活气。

**README 改成学生风格**
- 把像产品说明书的 README 改成第一人称、讲真实动机（生活费超支 + 练手）的版本；
- 保留了必要的技术信息，但语气更像一个学生写的，而不是 ChatGPT 写的。

### 收获

第一次完整走通「设计 → 编码 → 测试 → 构建 → 部署」闭环，最大的体会是：**项目不是写出来的，是「查错」查出来的**——每个坑都在逼我读懂框架的运行机制。
